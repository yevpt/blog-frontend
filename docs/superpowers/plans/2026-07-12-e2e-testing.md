# E2E 测试引入 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 monorepo 引入一层薄的 Playwright e2e，覆盖 web 登录冒烟与 admin 核心模块只读冒烟两条关键旅程。

**Architecture:** 新增独立 workspace `apps/e2e`（`private`，不参与 build），用 Playwright 的 `webServer` 同时拉起 web（生产构建）与 admin（dev，复用 `/api` 代理），网络指向 env 驱动的后端（本地 `http://localhost:8080` 或 staging）。web 登录本身即被测流程，故在用例内直接登录；admin 用 Playwright setup project 预登录并存 `storageState`，用例只做只读断言。

**Tech Stack:** Playwright（`@playwright/test`）、pnpm workspace、TypeScript。被测：Next.js 16（web）、Vite SPA（admin）、Go 后端（本地 `make dbsetup` 提供默认管理员账号）。

## Global Constraints

- 测试文件用 `*.spec.ts` / `*.setup.ts`（Playwright），与仓库 `*.test.ts(x)`（vitest）区分。
- 根 `vitest.config.ts` 必须 `exclude` 掉 `apps/e2e`，防止 vitest 收 e2e 文件。
- `apps/e2e` 标 `private: true` 且**不定义 `build` 脚本**（`pnpm -r --if-present build` 天然跳过）。
- 后端地址走环境变量 `E2E_BACKEND_API`；真实凭据只进本地 `.env`，仓库只提交 `.env.example`；`.auth/` 与 `.env` 必须 gitignore。
- 第一期只读，不做任何写操作（create/update/delete）；不接 pre-commit/pre-push/CI；只跑单一 Chromium。
- 提交信息遵循仓库 `commit-msg` 规范：`<type>(<scope>): <中文主题>`，scope 用 `e2e`。
- Node 22 / pnpm 11 环境。

## 已确认的实现事实（来自代码）

- **web 登录页** `apps/web/app/(auth)/login/page.tsx`：`identifier`（placeholder「用户名 / 邮箱」）+ `password`（placeholder「密码」）两个 input，提交按钮文案「登录」；成功后 `router.push(from ?? "/")`，登录态由 `/api/auth/login` route handler 下发 cookie。web 用 `API_BASE_URL` 指向后端。
- **admin 登录页** `apps/admin/src/app/LoginPage.tsx`：`username` + `password`，调 `apiClient.adminAuth.login`，`access_token` 存内存、`refresh_token` 存 `localStorage`。
- **admin 启动续期** `apps/admin/src/App.tsx` 启动即 `initSessionFromRefreshToken()`：读 localStorage 的 `refresh_token` 换 `access_token` → `AuthGuard`（看内存 `accessToken`）放行。故 storageState（含 localStorage）可保持登录。
- **admin 路由**：`/`（概览 index）、`/articles`（文章列表，侧边栏标签「文章」）等；未登录 `AuthGuard` 跳 `/login`。dev 态 `/api` 由 vite 代理到 `VITE_DEV_BACKEND_URL`。
- **后端账号**：`make dbsetup`（`cmd/dbsetup` + `internal/dbschema/seed.go`）幂等 seed 默认管理员，默认密码 `admin`（用户名见 seed 配置）。密码/admin 登录不需验证码。

```ts
import { test, expect } from "@playwright/test";

const identifier = process.env.E2E_WEB_IDENTIFIER ?? "admin";
const password = process.env.E2E_WEB_PASSWORD ?? "admin";

test("web 用户可用账号密码登录并进入首页", async ({ page }) => {
  await page.goto("/login");

  // 登录页两个输入框按 placeholder 定位，避免依赖 DOM 结构
  await page.getByPlaceholder("用户名 / 邮箱").fill(identifier);
  await page.getByPlaceholder("密码").fill(password);

  await page.getByRole("button", { name: "登录" }).click();

  // 成功后 router.push 到首页；断言已离开 /login 且无错误提示
  await expect(page).toHaveURL(/\/(?!login).*$|\/$/);
  await expect(page).not.toHaveURL(/\/login/);
  await expect(page.getByRole("alert")).toHaveCount(0);
});
```

- [ ] **Step 1: 写预登录 setup `apps/e2e/admin.setup.ts`**

```ts
import { test as setup, expect } from "@playwright/test";
import { fileURLToPath } from "node:url";
import { dirname, resolve } from "node:path";

const dir = dirname(fileURLToPath(import.meta.url));
const authFile = resolve(dir, ".auth/admin.json");

const username = process.env.E2E_ADMIN_USERNAME ?? "admin";
const password = process.env.E2E_ADMIN_PASSWORD ?? "admin";

setup("admin 登录并保存 storageState", async ({ page }) => {
  await page.goto("/login");

  // LoginPage 的用户名/密码输入框（按类型与顺序定位）
  await page.locator('input[type="text"]').first().fill(username);
  await page.locator('input[type="password"]').fill(password);
  await page.getByRole("button", { name: "登录" }).click();

  // 登录成功后离开 /login（accessToken 入内存、refresh_token 入 localStorage）
  await expect(page).not.toHaveURL(/\/login/);

  // storageState 会连同 localStorage 一并落盘（含 refresh_token）
  await page.context().storageState({ path: authFile });
});
```

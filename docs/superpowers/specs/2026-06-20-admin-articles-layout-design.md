# Admin 文章管理页布局优化设计

## 背景

当前 `apps/admin/src/modules/articles/ArticlesPage.tsx` 顶部有独立介绍区：图标、标题和说明文案占据较多高度，导致文章列表和高频操作被下推。文章管理页是后台高频列表页，首屏应优先服务筛选、搜索、创建、表格浏览。

本设计采用已确认的 B 方案：命令栏式列表页，并根据反馈进一步收敛为“极简标题 + 筛选带 + 右侧展开搜索 + 表格内滚动”。

## 目标

- 顶部只保留必要标题，不展示“管理发布、草稿与推荐位”这类说明文案。
- 去掉独立大图标标题区，减少顶部占高。
- 第二行左侧放真正有操作价值的筛选入口。
- 搜索默认收敛为右侧图标按钮，点击后向左展开为现代化 pill 搜索框。
- 去掉“置顶管理”按钮，后续通过表格操作列进入置顶配置弹窗。
- 缩小“新建文章”按钮，让它像列表页主操作而不是大 CTA。
- 页面主体固定在视口内，表格区域占据标题和筛选栏之外的剩余空间，并在表格容器内部滚动。

## 推荐布局

页面根节点改为高度约束布局：

- 外层：使用 `grid` 或 `flex` 纵向布局，目标高度为 admin 内容区可用高度。
- 第一行：极简页头。
  - 左侧仅 `文章管理` 标题。
  - 右侧小尺寸主按钮 `新建` 或 `新建文章`，使用 `@repo/ui` 的 `Button`，高度约 32-34px。
- 第二行：筛选带。
  - 左侧参考用户提供图片的 chip/filter bar。
  - 右侧放搜索入口，默认是图标按钮，点击后向左展开搜索框。
- 第三行：表格区域。
  - `DataTable` 的表格视图占据剩余高度。
  - 表头固定在表格容器内。
  - 表格内容在容器内滚动。
  - 分页和总数固定在底部，不触发页面级滚动。

## 第二行左侧内容

推荐常驻入口：

- `全部 42`
- `已发布`
- `隐藏`
- `加密`
- `分类`
- `更多筛选`

实现优先级：

- 第一阶段只落地已有能力：搜索、分类筛选、排序、分页。
- 状态 chips 若后端列表接口已支持 `status` 参数，则同步接入；若暂不支持，不做假筛选控件。
- `推荐/置顶` 不作为常驻 chip，先放入“更多筛选”的设计预留中。后续置顶能力通过操作列按钮打开置顶配置弹窗。

## 搜索交互

- 默认状态：右侧只显示圆形搜索图标按钮。
- 点击按钮：搜索框向左展开，自动聚焦。
- 输入为空且失焦：搜索框收回为图标按钮。
- 输入有值：保持展开，并显示清除按钮。
- 样式方向：圆角 pill、轻边框、细阴影、聚焦 ring，避免当前搜索框的普通输入框感。

如该搜索交互具有通用价值，优先在 `packages/ui` 扩展或新增可复用组件；如果只服务 admin 列表页，先放在 `apps/admin/src/modules/articles/components/` 或 `apps/admin/src/components/`。

## 表格高度与滚动

文章管理页应避免页面级滚动：

- `ArticlesPage` 根容器设置为可用高度布局。
- `DataTable` 外层和表格容器需要 `min-h-0`，避免 CSS Grid/Flex 子项撑开页面。
- 表格容器使用 `overflow-auto`，替代当前无限展开或固定 `max-h` 的行为。
- 底部分页保留在表格区域下方，和表格一起占用内容区，而不是跟随页面滚动。

如果 `DataTable` 当前 slot API 不足以完成该布局，应优先通过 `classNames` 扩展局部能力，避免为文章页复制一份表格实现。

## 删除与保留

删除：

- 顶部图标块。
- 顶部说明文案。
- `置顶管理` 按钮。

保留并调整：

- 标题 `文章管理`。
- 新建文章入口，缩小尺寸并放在第一行右侧。
- 文章表格现有列、分类筛选、服务端搜索、服务端排序和分页。

后续新增：

- 操作列增加置顶入口。
- 置顶配置弹窗。
- 需要后端能力配合的状态筛选或推荐筛选。

## 测试要求

根据仓库规则，页面改动需要同步更新 `ArticlesPage.test.tsx`：

- 标题仍可通过 heading 查询到。
- 不再出现说明文案和 `置顶管理` 链接。
- 新建入口仍存在，链接到 `/articles/new`。
- 搜索默认可通过按钮打开，展开后输入仍调用 `setSearch`。
- 分类筛选仍调用 `setCategoryId`。
- 表格排序仍调用 `setSort`。
- 分页仍调用 `setPage`。

若新增可复用搜索组件，还需要为该组件补充组件测试，覆盖展开、收起、聚焦、清除和有值时保持展开。

## 风险

- 表格内滚动需要仔细处理 `min-h-0`，否则仍可能出现页面级滚动。
- 状态 chips 需要确认后端接口能力，不能先做看似可用但无实际查询效果的控件。
- 搜索展开动画在窄屏下需要降级：移动端可展开为整行搜索框，避免挤压筛选 chips。

# 音乐编辑音频播放器设计

## 背景与目标

音乐管理的编辑表单当前直接展示完整音频 URL。签名参数使内容冗长且难以识别，也暴露了管理员不需要关注的存储细节。

本次将音频区域改为完整播放器：隐藏 URL，提供文件识别信息与就地试听能力，同时保留替换上传入口。不调整后端接口或提交字段。

## 界面设计

- 有音频时，从 `audioKey` 的 URL 路径解析并展示文件名，不展示域名、查询参数或完整链接。
- 播放器展示播放/暂停按钮、可拖动进度条、当前时间与总时长。
- 文件摘要展示格式、大小和总时长；编辑旧数据缺少大小或 MIME 时，仅隐藏缺失项，不显示错误占位。
- 操作按钮文案为“替换音频”；未选择音频时保持空状态并显示“选择音频”。
- 上传提示继续显示支持格式和 50MB 限制；上传中、上传失败和字段校验沿用现有表单反馈。

## 组件边界与数据流

- 扩展现有 `MusicPreviewButton` 的音频播放能力，形成可在列表和表单复用的播放器；列表继续使用紧凑模式，表单使用完整模式。
- 表单将 `audioKey`、曲名、时长、MIME 和大小传给完整播放器，不复制音频状态管理。
- 选择新文件并上传成功后，继续通过 `applyAudioUpload` 更新 URL、MIME、大小和 Hash；播放器随最新 URL 重置并加载新音频。
- 文件名解析使用独立纯函数：优先 URL pathname 最后一段并进行安全解码；解析失败时回退为“已上传音频”。

## 状态与异常

- URL 为空时禁用播放并显示未选择状态。
- URL 变化或组件卸载时暂停旧音频并重置播放进度。
- 浏览器拒绝播放或音频加载失败时恢复为停止状态，表单仍允许用户替换文件。
- 总时长优先使用媒体 metadata；加载前或不可用时使用表单已有时长。

## 测试与验收

- 纯函数测试覆盖普通 URL、带查询参数 URL、编码文件名和无效地址回退。
- 播放器组件测试覆盖文件信息渲染、播放/暂停、进度变化、拖动进度及 URL 变化重置。
- 音乐页面测试确认编辑表单不再展示完整 URL，改为文件名、完整播放器和“替换音频”。
- 运行 admin 定向测试、类型检查和 lint；现有音乐列表紧凑试听行为不得回归。

## 非目标

- 不增加删除音频、下载音频、波形可视化或倍速播放。
- 不变更上传接口、音乐保存接口及数据库字段。
